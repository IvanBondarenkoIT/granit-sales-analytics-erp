## Контекст и эталоны

- `D:\CursorProjects\granit-clients-based-segmentation` — эталон по доступу к БД и сегментации.
  В проекте сформирован список клиентов за год с телефонами (1700+); есть исходник,
  потом ручная правка; по списку разослали SMS о скидке.
- `D:\CursorProjects\monthly-sales-report` — анализ продаж за месяц в разрезе магазинов,
  групп товаров и параметра вроде «продукция».
- Возможный источник прогноза/кривых (найти точно):
  `granit-product-sales-tracker` или `granit-rests-pre-order` (или другой).

## Три целевые функции

1. **Эффект SMS-кампании**  
   Анализ продаж за период по клиентам, которым ушли SMS.  
   Вход: Excel с номерами телефонов и id клиентов.  
   Вопрос: были ли продажи у этих клиентов за выбранный период.

2. **UI аналитики продаж**  
   Удобная, неперегруженная визуализация / упорядочивание / группировка / сортировка
   продаж за период: по товарам, группам, параметру, клиенту, магазину и т.д.  
   Нужны понятные формы списка и «заказа» (среза).

3. **Анализ запущенных акций**  
   Вход: таблица текущих акций (на товар или группу).  
   После 1-й недели (потом 2-й): сравнить продажи с предыдущим периодом и с похожим
   периодом прошлого года (например медиана прошлого месяца и медиана того же периода
   год назад vs текущий уровень по дням). Решение: акция работает или вредит.  
   Опционально: кривая прогноза из старого проекта — сравнивать «сбылось ли».

## Целевой продукт (видение)

- Похоже на лёгкое ERP для решений, не замена учётной ERP.
- Своя БД PostgreSQL.
- UI frontend (предпочтительно Django).
- Зеркало/слепок рабочей ERP БД Granit: ночная синхронизация заказов, остатков и нужных
  сущностей — данные по вчерашний день.
- Ориентир на реальные продажи; не тянуть «мёртвый» ассортимент без продаж/остатков —
  только по мере продаж или остатков.

## Предполагаемый деплой / стек (предложение пользователя)

- Стек: Python + Django + Docker + PostgreSQL.
- БД (зеркало) на alt-сервере или remote Windows-сервере.
- Django API + интерфейс на Railway (чтобы не держать тяжёлую БД на Railway и не раздувать стоимость) —
  уже есть опыт и рабочие проекты.
- Альтернативы и лучшие идеи — обсудить с архитектором до финального промпта в Cursor.
