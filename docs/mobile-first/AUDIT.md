# Аудит интерфейса и целевая схема (24.11.2026)

Аудит: **по коду** `main` (коммит `18b8fd6`) — все шаблоны `templates/`, `*/templates/`, JS в шаблонах, CSS, тесты.
В браузере не мерился: на машине аудита не было Docker/Postgres и Playwright. Цифры (scrollWidth, поля < 16 px,
элементы < 44 px) снимет этап 0 — там же сверить этот аудит с фактом. Реальный телефон, язык `en`, выгрузка Excel
не проверялись.

## Вывод

Мобильной вёрстки нет совсем: ни одного `@media` во всём проекте, CSS — в `<style>` каждого шаблона, у страниц
`padding: 2rem`, таблицы на 6–10 колонок без обёрток. Переписывать логику не нужно — только шаблоны и общий CSS,
но объём больше, чем в service-center-erp: там была частичная адаптивность, здесь начинаем с нуля.

Главный сценарий на телефоне — **смотреть цифры** (продажи, супергруппы, сверка, кампании, эффект акции).
Создание/редактирование (акции с пикером товаров, редактор супергрупп, загрузка Excel кампании) — делаем
«работоспособно на телефоне», основной ввод остаётся на десктопе.
Это допущение аудита — если кто-то (Александр, магазины) реально вводит данные с телефона, этапы 6–7 надо усилить.

## Общие проблемы

- **Шапка:** 6 пунктов меню в одну строку (`.nav`, `display:flex` без переноса) + выход + выбор языка в `.topbar`
  с `padding: 0 2rem`. На 390 px гарантированно горизонтальный скролл страницы (подтвердить на этапе 0).
- **Нет общего CSS.** `static/` нет; `.btn`, `.hint`, `table`, `.stats`, `.empty` объявлены заново в 10+ шаблонах
  с разными отступами (`.btn` — 0.35/0.45/0.5/0.6 rem). Менять вид по одному шаблону дорого.
- **HTMX 1.9.12 с unpkg.com** — в `sales/explorer.html` и `promos/create.html`. Без CDN фильтры обозревателя и
  пикер акций не работают. Шрифты системные — это хорошо, качать ничего не надо.
- **Поля < 16 px** почти везде (`font: inherit` от 16 px body даёт 16, но в `.toolbar`, `.picker-filter`, `.lang-switch`,
  `.sel-table`, редакторе супергрупп — 0.85–0.9 rem) → iOS зумит при фокусе. `inputmode` не используется нигде,
  `type=number` для «Client ID» поднимает цифровую клавиатуру без `inputmode`.
- **Тап-зоны** < 44 px: выход-ссылка, выбор языка, `.btn-link` («Удалить», «Развернуть»), стрелки ↑↓ и кнопки
  в редакторе супергрупп (`padding .35rem .7rem`), чекбоксы пикера, ссылки-фильтры в кампании, ссылки в ячейках матрицы.
- `container` = `padding: 2rem` (64 px из 390 на поля), `h1` без размеров, на главной — `2.5rem` и hero 3rem.
- Нет `viewport-fit=cover`, `theme-color`, manifest. Футер «Admin Panel» на каждой странице.

## Целевая схема на телефоне (< 900 px)

- **Каркас:** плашка 52 px — «назад» на вложенных экранах, заголовок экрана, справа кнопка-аватар → `/more/#profile`.
  Язык, выход, Admin Panel — в «Ещё». Футер на телефоне скрыт.
- **Нижнее меню (для всех пользователей одинаковое):** Продажи · Супергруппы · Акции · Кампании · Ещё.
  «Ещё»: Сверка с Гранитом, Главная, Django-админка (только `is_staff`), язык, выход.
  Порядок пунктов — предложение; Иван может поменять в промпте этапа 2.
- **Общий паттерн аналитического экрана:** строка периода-фильтра свёрнута в `<details>`
  («01.11 – 24.11 · Розница · Все магазины ▾») → KPI-плитки 2 в ряд → список карточек `.table-cards`
  (название сверху, цифры справа) → итог липкой строкой внизу.
- **Обозреватель:** фильтры свёрнуты (раскрыты, только если активны нестандартные), «Группировать по» и «Сортировка» —
  чипы со скроллом над результатами, результаты карточками, итог «Строк · Кол-во · Сумма» сверху.
- **Супергруппы:** вместо матрицы — выбор магазина (чипы «Все · Магазин 1 · …») и список «супергруппа: сумма / кол-во»
  с цветной полоской; полная матрица остаётся на ≥ 900 px и доступна на телефоне кнопкой «Таблица» (горизонтальный скролл).
- **Сверка:** месяц — карточка со статусом-бейджем и разницей; магазины — карточки «Гранит / наши / разница».
- **Акция:** шапка (период, тип) → KPI 2 в ряд (Факт, к базе %, к прошлому году %, прогноз) → «Графики» →
  товары карточками. Графики читаемые на 390 px.
- **Формы (акция, кампания, супергруппы):** поля на всю ширину, основное действие в липкой панели, пикер — полноэкранный,
  дерево групп — над результатами в свёрнутом виде.
