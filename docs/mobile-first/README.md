# Mobile-first: рабочая папка

Здесь лежит всё по переводу интерфейса Granit Sales Analytics ERP (analytics.dimkava.ge) в mobile-first: правила,
промпты по этапам, статус и отчёты. Иван ставит задачу одной фразой, Cursor работает по этим файлам и пишет отчёт сюда же.
Claude читает отчёты и диффы прямо из репозитория для ревью — копировать текст между чатами не нужно.

Процесс тот же, что в `service-center-erp/docs/mobile-first`, отличия проекта — в `RULES.md` и `AUDIT.md`
(Django-шаблоны вместо Jinja, CSS внутри шаблонов, тесты `python manage.py test` на Postgres).

## Состав

| Файл | Что это | Кто пишет |
|------|---------|-----------|
| `README.md` | этот файл: порядок работы | Claude / Иван |
| `RULES.md` | правила, которые нельзя нарушать (контракт с JS, HTMX и тестами) | Claude / Иван; Cursor дополняет только по задаче этапа |
| `AUDIT.md` | что найдено в аудите 24.11.2026 и целевая схема экранов | Claude |
| `STATUS.md` | таблица этапов и их статус | Cursor обновляет после каждого этапа |
| `prompts/stage-N-*.md` | задача этапа | Claude / Иван |
| `reports/stage-N.md` | отчёт Cursor по этапу (по шаблону `reports/_TEMPLATE.md`) | Cursor |
| `reviews/stage-N.md` | замечания Claude по этапу (если есть) | Claude |

## Как запускать этап (для Ивана)

В Cursor, в новом чате агента, написать:

> Выполни следующий этап из docs/mobile-first

Или конкретный: `Выполни этап 3 из docs/mobile-first`.
Если по этапу есть `reviews/stage-N.md` с замечаниями: `Исправь замечания из docs/mobile-first/reviews/stage-N.md`.

После этого — сказать Claude «проверь этап N в granit-sales-analytics-erp», он прочитает отчёт и дифф ветки.

## Порядок работы (для Cursor)

1. Прочитай `STATUS.md`. Следующий этап — первый со статусом `todo` (или тот, что назвал Иван).
   Не начинай этап, если предыдущий не в статусе `done` или `review`, кроме случая, когда Иван прямо попросил.
2. Прочитай `RULES.md`, `AUDIT.md` и `prompts/stage-N-*.md` целиком.
3. Создай ветку из актуального `main`: имя указано в промпте этапа. Если ветка уже есть — продолжай в ней.
4. Поставь в `STATUS.md` статус `in_progress` и дату.
5. Сделай задачу этапа. Ничего сверх промпта: если видишь проблему вне этапа — запиши её в отчёт, не исправляй.
6. Проверки: `python manage.py test` (на локальном Postgres из `docker compose`), затем
   `python scripts/ui_snapshots.py --name stageN --compare <предыдущий прогон>` (с этапа 1; на этапе 0 скрипт создаётся).
   Если менял тексты — `python manage.py makemessages -l ru -l en` и `compilemessages`.
7. Напиши отчёт `reports/stage-N.md` по шаблону `reports/_TEMPLATE.md`. Пиши фактами: команды, цифры, пути.
   Не пиши «всё работает», если не проверял — так и укажи, что не проверено.
8. Поставь в `STATUS.md` статус `review`, ссылку на отчёт, имя ветки и последний коммит.
9. Закоммить изменения в ветку (код + отчёт + STATUS.md). **Не мержи в `main` и не пушь `main`**:
   push в `main` собирает образ `ghcr.io/ivanbondarenkoit/granit-sales-analytics-erp:main`, который выкладывается на прод
   (analytics.dimkava.ge) через deploy hub. Push самой ветки — только если Иван попросил (на PR запускается только CI-тест).
10. Остановись и коротко напиши Ивану в чат: что сделано, путь к отчёту, что проверить руками.

Если что-то в промпте противоречит `RULES.md` или коду — не угадывай: остановись, опиши в отчёте в разделе
«Вопросы» и поставь статус `blocked`.

## Статусы

`todo` → `in_progress` → `review` (ждёт проверки Claude/Ивана) → `done` (смержено в main)
`blocked` — нужен ответ Ивана, вопрос в отчёте. `rework` — есть замечания в `reviews/stage-N.md`.

Статус `done` ставит Иван (или Cursor по его просьбе) после мержа.

## Скриншоты

`scripts/ui_snapshots.py` (появится на этапе 0) кладёт скриншоты и `report.json` в `artifacts/ui/<прогон>/`.
Эта папка в `.gitignore` — в отчёте указывай путь и ключевые цифры из `report.json`, картинки не коммить.
